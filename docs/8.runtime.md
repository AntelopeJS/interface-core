## Overview

`@antelopejs/interface-core/runtime` exposes the runtime environment of the running project and a registry of development servers. The AntelopeJS core provides the implementation. `ajs project dev` reports `dev: true`, and `ajs project start` and `ajs project run` report `dev: false`. The package root re-exports everything in this module.

## Check the current mode

This check runs inside a running module whose behavior depends on development mode. The selected configuration environment (`env`) is separate from the command's development mode (`dev`).

```ts docs-check
import { GetRuntimeInfo } from "@antelopejs/interface-core/runtime";

const { dev, env } = await GetRuntimeInfo();
if (dev) {
  console.log(`Development helpers enabled for environment ${env}`);
}
```

Most consumers need only `GetRuntimeInfo`. The server registry below is for modules that open listening ports and for the tools that discover them. Registering an endpoint does not start a server.

## Import

```ts
import {
  GetRuntimeInfo,
  RegisterDevServer,
  DEV_REGISTRY_PATH,
} from "@antelopejs/interface-core/runtime";
```

## `GetRuntimeInfo`

Returns the runtime environment of the running project.

```ts
import { GetRuntimeInfo } from "@antelopejs/interface-core";

const info = await GetRuntimeInfo();
// { dev: true, projectPath: "/path/to/project", env: "default" }
```

| Field         | Description                                                    |
| ------------- | -------------------------------------------------------------- |
| `dev`         | `true` when running under `ajs project dev`, `false` otherwise |
| `projectPath` | Absolute path to the root of the running project               |
| `env`         | Name of the active configuration environment                   |

## `RegisterDevServer`

Registers a development server and the endpoints it listens on. A module that binds a network port, such as an HTTP API, calls it after a successful `listen()`. External tools then find the real endpoints.

```ts
import { RegisterDevServer } from "@antelopejs/interface-core";

await RegisterDevServer("api", [
  { protocol: "http", host: "localhost", port: 5011 },
]);
```

In development mode, the core merges the registration into the dev registry file and removes the file on shutdown. Outside development mode, the call is a no-op.

## Dev registry file

The dev registry file is at `DEV_REGISTRY_PATH` (`.antelope/dev.json`), relative to the project root. The `DevServerRegistry` type describes its shape. Each server is a `DevServerEntry`, and each endpoint is a `DevServerEndpoint`:

```json
{
  "pid": 12345,
  "startedAt": "2026-06-12T10:00:00Z",
  "servers": {
    "api": {
      "endpoints": [{ "protocol": "http", "host": "localhost", "port": 5011 }]
    }
  }
}
```

The file is valid only while the process identified by `pid` exists. If that process is gone, the file is orphaned, and a reader must ignore or overwrite it.
