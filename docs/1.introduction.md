## Overview

`@antelopejs/interface-core` lets one module call a contract that another module implements. The caller imports the interface, not the provider, so the runtime can connect modules and replace a provider without a change to the caller's imports.

If you only need application logs, start with [logging](./6.logging.md). If you use HTTP routes or authentication, start with those interfaces. You do not need to build a proxy first.

## Start with your role

| You are                       | Start here                                                                                                         | You own                                               |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| Calling an existing interface | Its package documentation, then [connection lookup](./2.proxies.md#getinterfaceinstances-and-getinterfaceinstance) | The consuming module and its provider binding.        |
| Defining a new contract       | [How interfaces work](#how-interfaces-work), then [proxies](./2.proxies.md)                                        | Typed declarations shared by consumers and providers. |
| Implementing a contract       | [`ImplementInterface`](./2.proxies.md#implementinterface)                                                          | Every declared function and registration callback.    |
| Integrating a module loader   | [Ownership](./2.proxies.md#ownership) and [module execution context](./5.modules.md#module-execution-context)      | Ownership contexts, generations, and cleanup.         |

An application module usually imports an existing interface and does not construct proxies itself. The AntelopeJS runtime supplies the module context and the connections. These primitives do not configure a project or choose a provider for you.

The package exports these groups of functionality:

- **Proxies.** `AsyncProxy`, `EventProxy`, and `RegisteringProxy` carry function calls, events, and registrations between modules. The runtime removes a module's attachments when the module is destroyed.
- **Interface functions.** `InterfaceFunction` declares a contract function, and `ImplementInterface` attaches an implementation to a declaration.
- **Decorator factories.** They build typed TypeScript decorators for classes, properties, methods, and parameters.
- **Metadata.** `GetMetadata` reads or creates metadata on an object and can inherit it from the prototype chain.
- **Module lifecycle.** Events and functions cover module construction, start, stop, and destruction.
- **Logging.** Structured logging on named channels, with several severity levels.
- **Configuration.** TypeScript types and the `defineConfig` helper for AntelopeJS project configuration.

## Import paths

The package exposes several entry points:

```ts
// The root: proxies, InterfaceFunction, ImplementInterface, GetMetadata, GetInterfaceInstances
import {
  AsyncProxy,
  InterfaceFunction,
  GetMetadata,
} from "@antelopejs/interface-core";

// Decorator factories
import {
  MakeClassDecorator,
  MakeMethodDecorator,
} from "@antelopejs/interface-core/decorators";

// Module lifecycle events and management
import {
  Events,
  ListModules,
  LoadModule,
} from "@antelopejs/interface-core/modules";

// Logging
import { Logging } from "@antelopejs/interface-core/logging";

// Configuration types and helpers
import { defineConfig } from "@antelopejs/interface-core/config";
```

## How interfaces work

An AntelopeJS interface is a contract between modules. One module declares the interface with proxy objects and `InterfaceFunction`. Another module provides the implementation with `ImplementInterface`. The proxies queue calls, track which module owns each attachment, and clean up when that module goes away.

```ts
// Declaration side: what the interface looks like
import { InterfaceFunction, EventProxy } from "@antelopejs/interface-core";

export const GetUser = InterfaceFunction<(id: string) => { name: string }>();
export const OnUserCreated = new EventProxy<(userId: string) => void>();
```

```ts fragment
// Implementation side: the concrete behavior
import { ImplementInterface } from "@antelopejs/interface-core";
import * as UserInterface from "./declaration";

ImplementInterface(UserInterface, {
  GetUser(id: string) {
    return { name: "Alice" };
  },
});
```

The proxy queues calls to `GetUser` until an implementation attaches. When the implementing module is destroyed, the proxy detaches it and queues new calls again. The queue holds at most 1,000 pending calls by default. In test stub mode, a call with no provider rejects at once. Read [proxy failure modes](./2.proxies.md#other-public-errors) before you depend on the queue during startup.

## Choose a communication primitive

| Need                                       | Primitive                           | Without an attached provider or listener               |
| ------------------------------------------ | ----------------------------------- | ------------------------------------------------------ |
| Ask for a result                           | `InterfaceFunction` or `AsyncProxy` | Calls queue, subject to the queue limit and stub mode. |
| Notify current listeners                   | `EventProxy`                        | The proxy keeps no emission for future listeners.      |
| Keep declarations available across reloads | `RegisteringProxy`                  | Entries stay stored and replay when handlers attach.   |

An event is the wrong tool for a registration that a replacement provider must recover. Use a registering proxy, and attach it with `onHandlers` when replay needs both the register and the unregister callback.
