## Overview

`Logging.Info` writes a status message to the main channel, and a named channel marks messages from one part of the application. These calls emit structured events. The runtime's listener decides how to display them. The interface itself writes no file and sends logs to no service.

## Write your first message

```ts docs-check
import { Logging } from "@antelopejs/interface-core/logging";

Logging.Info("Worker started");

const jobs = new Logging.Channel("jobs");
jobs.Info("Job completed", { jobId: "job-42", durationMs: 120 });
```

The first event uses channel `main`, and the second uses `jobs`. Both have level `INFO` (`20`). Inside an AntelopeJS project, the runtime's logging configuration decides whether they appear in the output. With no registered listener, nothing keeps an event for later display.

Log identifiers and outcomes, not credentials, tokens, or complete request bodies. Arguments reach listeners unchanged. This interface does not redact secrets or serialize objects.

Application code needs only the level and channel methods below. [Custom listeners](#listen-for-log-events) are for integrations that need their own output destination or format.

## Severity levels

The `Logging.Level` enum defines the available severity levels:

| Level       | Value | Purpose                                   |
| ----------- | ----- | ----------------------------------------- |
| `ERROR`     | 40    | Critical errors that may cause failure    |
| `WARN`      | 30    | Issues that do not prevent operation      |
| `INFO`      | 20    | General status updates and information    |
| `DEBUG`     | 10    | Detailed information for debugging        |
| `TRACE`     | 0     | Highly detailed tracing information       |
| `NO_PREFIX` | -1    | Messages displayed without a level prefix |

## Log to the main channel

The `Logging` namespace exposes functions that write to the `"main"` channel:

```ts
import { Logging } from "@antelopejs/interface-core/logging";

Logging.Error("Database connection failed");
Logging.Warn("Retrying database connection");
Logging.Info("Server started on port", 5011);
Logging.Debug("Request completed", { requestId: "req-42", status: 200 });
Logging.Trace("Entering function processItem");
```

Each function takes any number of arguments of any type (`...args: unknown[]`).

## Use named channels

A `Logging.Channel` instance writes to the channel it is named after:

```ts
import { Logging } from "@antelopejs/interface-core/logging";

const dbLog = new Logging.Channel("database");
const httpLog = new Logging.Channel("http");

dbLog.Info("Connection established");
dbLog.Error("Query failed", { operation: "listUsers" });

httpLog.Info("GET /api/users", 200);
httpLog.Debug("Response sent", { requestId: "req-42" });
```

A channel has the same methods as the main logging functions, `Error`, `Warn`, `Info`, `Debug`, and `Trace`, plus `Write`.

## Write at a custom level

`Write` logs at any numeric severity level:

```ts
import { Logging } from "@antelopejs/interface-core/logging";

// Static function on the Logging namespace
Logging.Write(25, "custom-channel", "Custom level message");

// Instance method on a channel
const channel = new Logging.Channel("metrics");
channel.Write(15, "Custom level within the metrics channel");
```

## Log entry structure

Each log entry that the event system emits has this shape:

```ts
interface Log {
  time: number; // Timestamp in milliseconds since epoch
  channel: string; // Channel name (e.g., "main", "database")
  levelId: number; // Numeric severity level
  args: unknown[]; // The logged values
}
```

## Listen for log events

A listener receives only the messages emitted after it registers. This example writes warning and error events to the console and ignores other levels.

```ts docs-check
import { Logging } from "@antelopejs/interface-core/logging";
import eventLog, {
  type Log,
} from "@antelopejs/interface-core/logging/listener";

function writeWarning(log: Log) {
  if (log.levelId < Logging.Level.WARN) return;
  const date = new Date(log.time).toISOString();
  console.warn(`[${date}] [${log.levelId}] [${log.channel}]`, ...log.args);
}

eventLog.register(writeWarning);
Logging.Warn("Retry scheduled");
// When this subscription is no longer needed:
eventLog.unregister(writeWarning);
```

Unsubscribing needs the same function reference. The runtime also removes a module's listeners when their owner is destroyed. A second console listener can repeat output that the runtime already writes.

Listeners run synchronously. A slow listener delays the logging call, and `emit` does not await promises from asynchronous listeners. Handle asynchronous failures inside the listener. Do not call `Logging.*` from a log listener. Each call emits another log event, and the recursion does not end.

The project's logging filters apply in the runtime's output listener. A custom listener receives raw events and applies its own filtering and redaction. `NO_PREFIX` is a level that formatters print without a prefix. It does not skip filtering or redaction.
