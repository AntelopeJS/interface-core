## Overview

`@antelopejs/interface-core/config` exports the `defineConfig` helper and the TypeScript types of an AntelopeJS project configuration. The types describe module sources, logging settings, environment overrides, config variables, and test configuration.

## Start with one local module

This is a complete `antelope.config.ts`. The source path is the module's directory. The module must already exist, because `defineConfig` does not generate it.

```ts docs-check
import { defineConfig } from "@antelopejs/interface-core/config";

export default defineConfig({
  name: "my-project",
  modules: {
    app: {
      source: { type: "local", path: "./modules/app" },
    },
  },
});
```

`defineConfig` returns its input unchanged. It adds TypeScript checking, and no runtime validation or module loading. The source and field reference below covers more modules. Config variables and provider overrides are optional.

## Import

```ts
import { defineConfig } from "@antelopejs/interface-core/config";
import type {

  ModuleSourcePackage,
  ModuleSourceLocalFolder,

```

## `defineConfig`

`defineConfig` type-checks a configuration. It accepts a configuration object, or a function that receives a `ConfigContext` (`{ env: string }`) and returns a configuration or a promise of one.

```ts
import { defineConfig } from "@antelopejs/interface-core/config";

// Static configuration
export default defineConfig({
  name: "my-project",
  modules: {
    database: "@antelopejs/database",
    auth: {
      version: "1.0.0",
      source: {
        type: "package",
        package: "@antelopejs/auth",
        version: "1.0.0",
      },
      // Supply provider-specific configuration through your deployment's secret handling.
    },
  },
});
```

```ts
import { defineConfig } from "@antelopejs/interface-core/config";

// Dynamic configuration based on environment
export default defineConfig((ctx) => {
  return {
    name: "my-project",
    modules: {
      database: {
        source: {
          type: "package",
          package: "@antelopejs/database",
          version: "1.0.0",
        },
        config: {
          host: ctx.env === "production" ? "db.prod.internal" : "localhost",
        },
      },
    },
  };
});
```

## `AntelopeConfig`

The root configuration object of an AntelopeJS project.

| Property       | Type                                             | Description                                     |
| -------------- | ------------------------------------------------ | ----------------------------------------------- |
| `name`         | `string`                                         | Project name                                    |
| `cacheFolder`  | `string`                                         | Optional custom cache directory                 |
| `modules`      | `Record<string, string \| AntelopeModuleConfig>` | Optional module definitions (shorthand or full) |
| `logging`      | `AntelopeLogging`                                | Optional logging configuration                  |
| `envOverrides` | `Record<string, string \| string[]>`             | Optional environment variable overrides         |
| `environments` | `Record<string, Partial<AntelopeConfig>>`        | Optional per-environment config overrides       |
| `test`         | `AntelopeTestConfig`                             | Optional test configuration                     |

## Module sources

Each module source type says where the module code is and how to load it. Every source type also accepts an optional `id` and `ignoreCache`.

### Local source

A local source loads a module from a local file path:

```ts
import { AntelopeModuleConfig } from "@antelopejs/interface-core/config";

const config: AntelopeModuleConfig = {
  source: {
    type: "local",
    path: "./modules/my-module",
    main: "index.ts",
    watchDir: "src",
    installCommand: "pnpm install",
    reloadCommand: "pnpm build",
  },
};
```

The optional `reloadCommand` runs in place of `installCommand` on hot reload. It can be a shorter command chain, for example one without `pnpm install`.

### Git source

A Git source loads a module from a Git repository. It also accepts an optional `commit`.

```ts
import { AntelopeModuleConfig } from "@antelopejs/interface-core/config";

const config: AntelopeModuleConfig = {
  source: {
    type: "git",
    remote: "https://github.com/org/module.git",
    branch: "main",
    installCommand: "pnpm install",
  },
};
```

### Package source

A package source loads a module from an npm package:

```ts
import { AntelopeModuleConfig } from "@antelopejs/interface-core/config";

const config: AntelopeModuleConfig = {
  source: {
    type: "package",
    package: "@antelopejs/database",
    version: "1.0.0",
  },
};
```

### Local folder source

A local folder source loads a module from a local folder, with optional file watching:

```ts
import { AntelopeModuleConfig } from "@antelopejs/interface-core/config";

const config: AntelopeModuleConfig = {
  source: {
    type: "local-folder",
    path: "./packages/shared",
    watchDir: ["src", "lib"],
    installCommand: ["pnpm install", "pnpm build"],
    reloadCommand: "pnpm build",
  },
};
```

Like the local source, `local-folder` accepts an optional `reloadCommand` that runs in place of `installCommand` on hot reload.

## `AntelopeModuleConfig`

The full configuration of one module in the project configuration.

| Property          | Type                                         | Description                                                                                                                              |
| ----------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `version`         | `string`                                     | Optional version constraint                                                                                                              |
| `source`          | `ModuleSource*`                              | Optional source definition (local, git, package, local-folder)                                                                           |
| `config`          | `unknown`                                    | Optional runtime configuration                                                                                                           |
| `importOverrides` | `ImportOverride[] \| Record<string, string>` | Optional providers pinned for the interfaces the module uses, and named connections                                                      |
| `disabledExports` | `string[]`                                   | Optional list of exports to disable                                                                                                      |
| `exportPriority`  | `Record<string, number>`                     | Optional priority of this module as the default provider of each interface it implements (default 0; highest wins)                       |
| `disabled`        | `boolean`                                    | Keeps the module declared, with its configuration, without loading it                                                                    |
| `optional`        | `boolean`                                    | Loads the module once the others have started; a failure to download, construct or start it is logged and the project runs on without it |

An `ImportOverride` is `{ interface, source?, id? }`. The first entry for an interface pins it to the `source` module. Further entries are connections reached through `GetInterfaceInstance(interface, id)`. An entry for a standalone interface may omit `source`. It then declares a connection to that self-hosted interface.

`SaveModuleDeclaration` uses this project-file contract too. It differs on purpose from the runtime `ModuleDefinition.importOverrides: Record<string, string[]>` that `LoadModule` accepts, and the two types are not interchangeable. Use the type of the API you call. Do not change or cast the override shape.

## `AntelopeLogging`

The core runtime reads this logging configuration. Every field is optional. The settings configure the runtime's output. They do not change the raw events sent to a [custom logging listener](./6.logging.md#listen-for-log-events).

| Property         | Type                                 | Description                                               |
| ---------------- | ------------------------------------ | --------------------------------------------------------- |
| `enabled`        | `boolean`                            | Enable or disable logging                                 |
| `moduleTracking` | `{ enabled?, includes?, excludes? }` | Track module-level logging with include and exclude lists |
| `channelFilter`  | `Record<string, number \| string>`   | Filter log output by channel and level                    |
| `formatter`      | `Record<string, string>`             | Custom formatters per channel                             |
| `dateFormat`     | `string`                             | Date format string for log timestamps                     |

## Config variables

A module can publish named values that other modules reference from their own configuration. The provider declares the names it publishes under `antelopeJs.configVars` in its `package.json` and returns the values from its `provide` callback. The core substitutes them into every consumer before any module constructs.

```json
{
  "name": "api",
  "antelopeJs": {
    "configVars": ["API_PORT"]
  }
}
```

```ts fragment
import type { ConfigVars } from "@antelopejs/interface-core/config";

export async function provide(config: unknown): Promise<ConfigVars> {
  const port = await reservePort(config);
  return { API_PORT: port };
}
```

`provide` is optional, and only providers implement it. It runs before every `construct`. No other module has constructed yet, so awaiting another module's interface from `provide` deadlocks the startup. The core interfaces registered before the module lifecycle starts, `GetRuntimeInfo()` among them, stay available. They are enough to compute a port, a base URL, or a generated secret.

A consumer references the value with `${@<moduleName>.<VAR_NAME>}`, where `<moduleName>` is the module's key in the project configuration:

```ts
import { defineConfig } from "@antelopejs/interface-core/config";

export default defineConfig({
  name: "my-project",
  modules: {
    api: { version: "1.0.0" },
    dms: {
      version: "1.0.0",
      config: { apiBaseUrl: "http://127.0.0.1:${@api.API_PORT}" },
    },
  },
});
```

| Type                                  | Definition                                                              | Description                                                                                  |
| ------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `ConfigVarValue`                      | `string \| number \| boolean`                                           | A single published value                                                                     |
| `ConfigVars`                          | `Record<string, ConfigVarValue>`                                        | The record `provide` returns                                                                 |
| `ConfigVarProvider<Config = unknown>` | `(config: Config) => Promise<ConfigVars \| void> \| ConfigVars \| void` | The signature of the `provide` callback; `Config` types the module configuration it receives |

The core resolves the values once, before construction, and never again. `construct` cannot publish config variables, because the core ignores its return value. The core documentation describes the resolution order and the failure modes.

## `AntelopeTestConfig`

The project's test configuration.

| Property  | Type                                                             | Description                                           |
| --------- | ---------------------------------------------------------------- | ----------------------------------------------------- |
| `folder`  | `string`                                                         | Optional test folder path                             |
| `setup`   | `() => Partial<AntelopeConfig> \| undefined`, or a promise of it | Optional setup function that returns a partial config |
| `cleanup` | `() => void \| Promise<void>`                                    | Optional cleanup function                             |
